Slash commands and CLAUDE.md: give Claude a memory

A handful of slash commands cover almost everything you'll do day to day. One of them creates a file that makes every future session smarter.

AgentDrills team · Updated November 23, 2026 · 6 min read

Inside Claude Code, there are two kinds of input. Plain text is a message to Claude, the model. Text that starts with a / is a slash command: an instruction to Claude Code, the tool. Slash commands don't go to the model as a question. They change the session itself: clear it, summarize it, show help, quit.

Type a single / and a list appears. Keep typing to filter it, use the arrow keys to move, Tab to complete and Enter to run. You don't need to memorize the full list, but a few commands are worth knowing by heart.

The everyday commands

CommandWhat it does
/helpShows how to use Claude Code and the available commands.
/initAnalyzes your project and writes a CLAUDE.md file with key facts about it.
/clearWipes the conversation and starts fresh in the same folder.
/compactReplaces the conversation with a short summary to free up space.
/contextShows how much of Claude's working memory is in use.
/memoryOpens your memory files (like CLAUDE.md) for editing.
/modelSwitches which Claude model the session uses.
/exitQuits Claude Code.

The most common mistake is forgetting the slash. clear on its own is a message, and Claude will try to answer it. The second most common is a typo like /inti. The autocomplete list is there to save you from both.

CLAUDE.md: the most underrated file in your project

Every new Claude Code session starts with a blank memory. Claude can read your code, but it doesn't know your conventions: how you run tests, which folder is off limits, that you prefer plain functions over classes. Without that, you end up repeating the same instructions every day.

CLAUDE.md fixes this. It's a normal Markdown file in the root of your project, and Claude Code automatically reads it at the start of every session. Whatever you write there, Claude knows from the first message.

Creating it with /init

You can write the file by hand, but the fastest start is:

> /init

Claude reads through the project (package files, README, folder structure) and writes a first version. A typical result looks like this:

# CLAUDE.md

## Commands
- `npm test` – run unit tests
- `npm start` – serve the app on :3000

## Code style
- Plain ES modules, no frameworks
- Persist data only through src/storage.js

Treat this as a draft. Read it, correct anything that's wrong, and add what only you know.

What belongs in CLAUDE.md

  • Commands: how to install, run, test and lint the project.
  • Structure: where the important code lives and what each folder is for.
  • Rules: "never edit files in generated/", "all user-facing text must be in English", "ask before installing packages".
  • Style: naming, formatting and patterns you want followed.
  • Gotchas: the things that tripped up the last person (or AI) who worked on it.

What doesn't belong there

  • Secrets, passwords or API keys. CLAUDE.md is usually committed to your repository.
  • Long documentation Claude can read from the code itself.
  • One-off instructions for today's task. Just say those in the chat.
Keep it short. Everything in CLAUDE.md is loaded into every session and uses up context. A focused page beats a ten-page manual.

Besides the project file, you can have a personal one in your home folder (~/.claude/CLAUDE.md) for preferences that apply to all your projects, like "explain things simply" or "always answer in British English".

Practice the commands

Run /help, create a CLAUDE.md with /init, check your context and clear the session.

/clear vs /compact: which one when?

Both commands free up Claude's working memory, but in different ways:

  • /clear forgets everything in the conversation. Use it when you switch to an unrelated task. Old messages about yesterday's bug only distract Claude from today's feature.
  • /compact keeps a summary and drops the details. Use it in the middle of a long task when you want to continue but the conversation has grown huge.

In both cases, CLAUDE.md is still loaded. That's the beauty of it: the conversation is temporary, the memory file is not. If you find yourself telling Claude the same thing after every /clear, that's a sign it belongs in CLAUDE.md.

Make your own slash commands

Once you notice yourself typing the same instructions again and again, you can turn them into your own command. Custom commands are just Markdown files in a .claude/commands/ folder in your project. The file name becomes the command name, and the file's content is the prompt Claude receives.

For example, a file at .claude/commands/review.md containing

Review the changes since the last commit.
Look for bugs, missing tests and unclear names.
List problems by severity. Don't change any files.

gives you a /review command that runs that exact checklist every time. Because the folder lives in your project, you can commit it, and everyone on your team gets the same commands. Good candidates are routines you do often and want done the same way: reviewing changes, writing release notes, preparing a commit message, or checking a page on mobile.

Start small. One or two commands that you actually use beat a folder of twenty you forget about. And as with CLAUDE.md, keep each one short and specific.

A simple habit to adopt

At the end of a session where you corrected Claude on something important, ask it to update the memory:

> add a note to CLAUDE.md that dates must always be stored in UTC

Over a few weeks, your CLAUDE.md turns into a sharp, project-specific guide, and every session starts smarter than the last.

Claude Code is updated often, and the list of commands grows over time. Type / inside Claude Code to see what your version offers.
